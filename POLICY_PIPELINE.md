# Массовая проверка правил поступления

## Что считается проверенным

Каталог содержит 5 002 учреждения из федерального выпуска College Scorecard от 19 мая 2025 года. Это исторические показатели с **разными отчётными годами**, а не подтверждение текущей стоимости, допуска иностранных студентов, наличия полной стипендии или действующей аккредитации. Новый федеральный CSV необходимо получить из официального источника и отдельно проверить его выпуск и состав; этот релиз сайта не обновляет федеральный набор.

Пять правил поступления — international financial aid, SAT/ACT, английский, application fee, дедлайны — проверяются независимо. Состояния опубликованных полей: `pending`, `verified`, `conflict`. Автоматически найденные фрагменты остаются кандидатами в локальной рабочей папке и не попадают в число подтверждений. Профиль полностью проверен только при пяти подтверждённых полях. Непроверенное значение — неизвестно, а не «нет». Отсутствие application fee не означает существование fee waiver; full need не означает need-blind.

Дата проверки показывает, когда редакция прочитала страницу, а не когда университет гарантировал неизменность условий. Цикл `2026–27` — цикл редакционного аудита; если источник не указывает год набора, сам по себе этот ярлык не подтверждает срок для Fall 2027. Условия всегда следует перепроверить перед подачей. Статистика приёма и число полных стипендий не выводятся из правил финансовой помощи.

## Первое внедрение, 3 октября 2026

- Сохранены 58 полных редакционных аудитов; их старые подтверждения не дополнены выдуманными цитатами.
- Ещё 12 учреждений получили 24 подтверждённых требования: Mount Holyoke, Reed, Connecticut College, Dickinson, Bard, Knox, Beloit, Lawrence, DePauw, Earlham, Sarah Lawrence, Gettysburg.
- Итого 314 подтверждённых требований из 25 010 возможных. 70 учреждений имеют хотя бы одно подтверждённое требование, но **не 70 полных аудитов**.
- У Gettysburg обнаружено противоречие ED II: 20 января для заявления и 15 января для формы ED на одной странице. Поле остаётся `conflict`, не участвует в подтверждениях и показывает предупреждение.
- Дедлайны Dickinson и Connecticut, английский Reed и другие незавершённые поля намеренно не повышены до проверенных. Правила graduate-программ Bard не смешиваются с undergraduate Bard College.

## Рабочий процесс

Запускать из корня репозитория с Node.js 22+. Прямой доступ к интернету необходим только для сбора и проверки ссылок. Браузер посетителя эти задачи не запускает.

```text
npm run audit:policies -- summary
npm run audit:policies -- queue --limit 30
npm run audit:policies -- collect --limit 20 --pages 3 --resume
npm run audit:policies -- collect --limit 4 --pages 3 --ids 166939,209922,128902,212009
npm run audit:policies -- changes
npm run audit:policies -- approve --file data/policy-review-batches/2026-10-03.json
npm run build:data
npm test
```

`queue` охватывает каталог целиком. Приоритет: изменившиеся страницы, известные официальные маршруты и частичные проверки, затем учреждения с преимущественно bachelor's-программами, private nonprofit и более высокой долей nonresident students. Это очередь для работы, **не рейтинг качества или вероятность стипендии**. Сортировка имеет стабильный tie-break по IPEDS ID.

`collect` ограничен 500 учреждениями и 8 страницами на учреждение; по умолчанию 10 × 3. `--parallel 4` одновременно обрабатывает до четырёх групп официальных доменов (максимум 8), сохраняя последовательный обход внутри группы. `--unseen` выбирает ещё не посещавшиеся учреждения. Источники сопоставляются по точному IPEDS ID. Ручные маршруты и допустимые домены задаются в `data/policy-source-manifest.json`; иначе стартом служит официальный адрес из федеральной записи. Если стартовая ссылка устарела, сборщик пробует главную страницу того же сайта и ищет актуальные ссылки. Типовые служебные поддомены admissions/apply могут перенаправляться внутри домена учреждения. Приоритет получают international/first-year requirements и financial aid; graduate, transfer и служебные страницы идут ниже.

Сборщик обрабатывает HTML, соблюдает robots.txt, принимает только HTTPS, проверяет домен/редиректы и отбрасывает частные адреса, CAPTCHA, пустые страницы и файлы сверх 2 МБ. PDF, заблокированные сайты и неутверждённые внешние домены отправляются на ручную проверку, а не превращаются в факты. Нельзя обходить ограничения сайта отключением TLS или маскировкой под Googlebot.

`--resume` пропускает уже сохранённые неизменённые начальные страницы. Без этого флага страницы перечитываются и сравниваются по SHA-256 нормализованного основного текста. При изменении алгоритма извлечения прежние хэши не используются для тревоги. Изменившийся текст — сигнал для перепроверки, не доказательство изменения конкретного правила. `changes` возвращает такие источники, а очередь повышает их приоритет, в том числе у ранее полностью проверенных вузов. Обновление не запускается само по расписанию; для повторного мониторинга нужно повторно запустить сбор.

Рабочие результаты в `.policy-cache/`: полные снимки, их хэши и кандидаты по темам, `state.json`, `queue.json`, `last-batch.json`. Папка исключена из Git и **не загружается посетителям**. Ошибки отдельных вузов не теряют результаты остальных. После перезапуска сбор продолжается через `--resume`.

## Как подтверждать поля

1. Открыть снимок нужного IPEDS ID и официальный источник. Проверить, что это именно undergraduate first-year international, нужный кампус, нужный цикл; прочитать исключения и связанные страницы. Поиск ключевого слова не заменяет это чтение.
2. Подготовить JSON по образцу `data/policy-review-batches/2026-10-03.json`: `status`, точное описание `value`, `source`, `checkedAt`, `cycle`, `method: editorial`, `reviewer`, `evidence.hash`, короткая дословная `evidence.quote` (до 25 слов).
3. Добавлять структурированные `attributes` только при наличии прямого подтверждения: `needBlind`/`aidCategory`/`aidShort` относятся к aid, `testFlexible` к testing, `englishStatus` к english, `feeWaiver` к fee. При отсутствии доказательства атрибут неизвестен. Не присваивать need-aware только из наличия need-based aid.
4. Выполнить `approve`: сначала проверяется **вся партия**, включая ID, домен, дату, цикл, поле, тип атрибута, совпадение хэша снимка, даты чтения и цитаты. Только после успеха объединяются записи в `data/policy-field-reviews.json`. Чужой ID, выдуманная цитата или изменённый снимок отклоняют партию целиком. Снимки необходимы для повторного подтверждения; опубликованного хэша без исходного текста для этого недостаточно.
5. Пересобрать данные, выполнить тесты и проверить страницу/сравнение. Одобрение не публикует сайт автоматически.

Конфликт не решается выбором более удобной страницы: записать `conflict` и выяснить верный вариант у admissions. У старых полных аудитов метод `legacy-editorial` сохраняет прежние ссылки и даты, но не утверждает наличие снимка/цитаты, которых тогда не записывали.

## Скорость сайта и проверки

### Редакторские вспомогательные инструменты

`node scripts/compile-policy-review.mjs <spec.json> <proposal.json>` собирает вручную написанные утверждения из спецификации, подставляет даты и хэши ранее сохранённых источников и проверяет доказательства. Существующий файл не перезаписывается. Команда не одобряет и не публикует данные.

`node scripts/import-policy-source.mjs <excerpts.json>` сохраняет уже полученные и вручную просмотренные выдержки официальных страниц из `web.open`. Они помечаются `retrieved-excerpt`, а не полными HTML-снимками; исходная ошибка прямой загрузки сохраняется отдельной записью. Инструмент не обходит robots, CAPTCHA или проверку TLS и не подтверждает поля автоматически. Локальные исходные выдержки не публикуются.

Начальный индекс хранит только битовую маску подтверждений и значения для фильтров. Тексты правил и цитаты живут в 128 ленивых файлах деталей. Новый код не скачивает тысячи источников на устройство пользователя и не требует API-ключей в браузере.

`test-policy-pipeline.mjs` проверяет точные ID, статусы, частичные/полные проверки, неизвестные флаги, домены, локальные адреса, robots, даты и доказательства. `test-policy-browser.mjs` проверяет все новые поля в профилях, частичный фильтр, счётчики, ссылки/цитаты, неизвестные флаги и режим отличий в сравнении, конфликт и мобильный экран. Оба включены в CI. Проверка HTTP-ссылок отдельно сообщает доступность/ограничение доступа; HTTP 200/403 никогда не считается проверкой политики.
